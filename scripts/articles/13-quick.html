赛道地图

三种建设责任，不能塞进一张总榜

描述一个方案至少要同时说清：交付形态（成品 / 平台 / 框架）、用途（Coding / 助手 / 业务自动化）和运行方式（托管 / 自托管 / 本地）。例如 Codex CLI 既可直接当 Coding 成品，也可作为改造底座；Dify 是建设平台，用它交付的业务才接近成品。

建设对象读者要核对的入口不能直接推出的结论
成品使用者公开说明、真实任务、审查与发布边界官方演示不等于你的代码库成功率
平台 / 知识工作台连接器、执行语义、权限、状态、部署和升级能搭建不等于跨实例恢复可靠
框架 / SDK / runtime普通 loop、图、暂停审批、跨实例恢复功能存在不等于业务副作用 exactly-once
可改造 Coding 核心核心语言、文件 / 终端 / 隔离边界、维护成本开放核心不等于产品层能力完整

快速读者的判断入口是：先看你必须维护什么。不想维护执行核心，就验证成品；想复用业务连接器但保留定制空间，就评估平台；必须控制模型循环、工具权限、状态和恢复，才进入框架 / 自建比较。

语言选择

主控语言跟着运行方式和关键依赖走

Harness 是把 Agent 动作执行下去的运行底座，管理模型循环、上下文、工具、权限和执行状态。主控语言决定这套控制逻辑怎样开发、运行和维护；它不要求模型服务、Python 工具或浏览器环境改成同一种语言。

Java 边界

Java 什么时候优先，什么时候另算成本

Java 团队建设常驻 Agent 服务时，Java 值得优先验证：它可以直接拥有执行循环、动作策略和任务状态。虚拟线程适合表达等待模型流、工具输出或用户输入；record / sealed 类型能帮助表达任务状态契约；堆、线程、GC 和 JFR 可用于长期诊断。

统一例子修复 Java Bug 并运行测试

Java 主控可以读取仓库、保存候选动作、调用 Maven / 测试工具，并把退出码、日志和改动交回模型。这里选 Java 是因为主控和现有工程在同一生态；不是因为“Java 只能改 Java”。Maven 继续启动哪些子进程、测试环境如何回收，仍要单独验证。

最容易误判的是取消边界：取消 Java Future 不能证明 Maven、测试进程或浏览器工具已经停止；Go context 也不自动解决所有后代进程。要检查执行环境如何回收进程、管道和授权。

边界Java 能帮上什么还必须另验什么
服务端等待与并发虚拟线程表达等待；接口与类型表达状态模型配额、锁竞争、状态大小和失败重试
长期诊断堆、线程、GC、JFR 定位等待和执行事件无界上下文、工具输出和租户热点
本地交付jpackage 或 Native Image 提供候选路径包体、启动、内存、反射 / 资源 / JNI
安全隔离进程编排与权限入口可以由主控记录不可信命令放到匹配威胁模型的沙箱

版本条件：虚拟线程在 JDK 21 正式提供；JDK 24 通过 JEP 491 减少 synchronized 引发的 pinning。这不替代超时、配额、状态恢复和进程清理。

最后一步

用真实任务和失败注入收束选型

仓库热度只能入围，不能验收。第一版先让一个明确任务从输入走到可审查产物：主控拥有动作策略，工具执行结果可追踪；恢复时显式保存阶段和动作标识，不因跨语言自动引入消息队列、MCP、A2A 或多个 Agent。

证据强度升级规则：官方功能说明支持“入围”；使用者工程公开说明支持“这条路有人走通”；具名客户案例支持“已部署”，但不等于独立可靠性审计；公开研究支持“该设定下有效”；只有你自己的固定任务和失败注入，才能支持“采用这个方案”。
常见读法校正该去看什么
开源核心是 Rust，所以产品一定最适合本地终端核心语言只约束你改造的那一层，产品层和工具层可能不同成品边界、SDK、部署方式
工具是 Python，所以主控也要 Python主控语言和工具进程语言可以分开工具契约、状态、失败恢复
Stars 高，说明适合生产Stars 只是候选集内累计关注维护迹象、真实使用、目标验证
支持 checkpoint，外部动作就安全控制流恢复不等于外部写入 exactly-once幂等键、查询结果、授权与失败窗口

至少验证进程中断、工具超时、取消、审批后重启和状态升级。保存 checkpoint 不让外部动作 exactly-once：通知已发送但响应丢失时，恢复后重新执行可能再次通知；幂等键、查询结果和授权要由具体工具契约处理。

验证项观察什么不能只看什么
端到端任务输入到可审查产物、原需求覆盖单步工具调用成功
失败注入中断、超时、取消、审批后重启、状态升级正常路径一次通过
外部副作用幂等键、查询结果、授权、失败窗口checkpoint 已保存
成本与协作成功率、人工返工、总耗时、总费用Stars 或演示视频
  1. 先锁定一个可审查目标任务和原需求。
  2. 给主控加上动作追踪、状态版本与失败分支。
  3. 让两三个候选跑同一批任务，保留日志和产物。
  4. 制造中断、超时、取消和审批后重启。
  5. 按成功率、返工、耗时、费用和恢复质量决定。
