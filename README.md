# show-something

九篇关于 AI 时代工程实践的深度文章：每篇都有一份**经得起逐段拷问的深入版（md）**，另配**一份 10 分钟读懂的讲解版（html，带图）**。

选题集中在编码 Agent 真正会咬人的地方：需求如何变成可验证契约、为什么"看起来正确"变廉价了、提示词与代码的边界在哪、"越聊越浅"与"越聊越乱"分别是什么机制、以及 Claude Code 与 Codex 的协作可靠性实证；新增文档知识库的可归因回归、Agent 离线与生产评测闭环、陌生后端事实核验。

## 怎么读

| 你是谁 | 读什么 | 位置 |

## 目录

```
show-something/
├── 原文/        深入版 md（断言标注、因果链、证据边界）——01~09 全九篇，每篇一份
├── 来源/        素材与旧版备份，不进入阅读路径（_旧版/ 存被替换的历史稿）
├── 复核/        本轮选题、命题去向、核验及证据边界
├── project.json 本轮新增三篇的配对与交付配置
└── 阅读/        九篇讲解版 html + 总目录 index.html（单文件、内联图解、离线可读）
```

**这两个目录的分工，只有一条规则**：一篇只有一份深入版，放 `原文/`；`来源/` 只放素材和已被替换的旧稿，任何页面都不链接它。所以「有原文就不看来源」不是习惯，是约定——当前阅读路径不链接 `来源/`。历史约定提到的 `check_show.py` 未随仓库交付；本轮用展示规范检查器与真实浏览器检查，范围见本轮核验记录。

## 关于这套写法

前六篇与本轮新增三篇分别有各自的制作与核验记录。前六篇不是一次写成的稿子。它们先经过逐篇拷问（正确性 / 是否说清楚 / 条理与通俗度），把"立论前提裸奔、表格代替论证、虚构案例冒充普遍现象、全文无图"这类问题逐条定位并修掉，再由**与写作分离的独立视角**进行复核；历史评分描述不作为新增文章已经发布的证明。

**知道自己哪里写得不行，是这套流程能起作用的前提**。历史诊断由作者本地留存；本轮 07–09 的选题与核验记录位于 `复核/`，不把旧验收延用为本轮结论。
