# 项目维护规范

> 版本：1.0｜生效：2026-11-13｜适用：show-something

## 1. 目录归属

根目录保留 `README.md`、`index.html`、`.gitignore` 三个文件，以及 `原文/`、`来源/`、`阅读/`、`工程/` 四个目录。构建器按 `config/project.json` 的 `repository_layout` 检查此约定；新增工程文件按下表归位。Git 自身元数据和被忽略的系统文件不属于公共内容。

| 位置 | 归属与维护方式 |
|---|---|
| `原文/` | 正式 Markdown 文章；文件名和发布路径保持可追溯 |
| `来源/` | 来源材料与历史稿；保留用户指定材料，直接存放现有文件 |
| `阅读/` | 文章 HTML、`配图/` 与 `数据/`；保留既有文章 URL |
| `工程/assets/` | 站点及阅读页共享的 CSS、JavaScript、图标、封面 |
| `工程/config/` | `posts.json` 文章目录、`featured.json` 推荐、`project.json` 项目配对与目录约束、`article_manifest.json` 文章构建清单 |
| `工程/scripts/` | 构建脚本、`articles/` 图解源片段、`site-templates/` 页面模板、`vendor/` 本地依赖与许可证 |
| `工程/pages/` | 分类页等辅助页面，当前由构建器生成 `category.html` |
| `工程/复核/` | 本地检查记录、截图与过程材料，统一被 Git 忽略 |

增加文件时先确定归属，构建产物由源文件生成。需要新增根目录项或删除来源材料时，以用户确认的目录方案为准。目录整理应保留来源身份和正文，只在需要时修正导航链接。

## 2. 内容与构建

15 篇正式文章由 `config/posts.json` 登记。11–15 的完整深入版从 `原文/` 渲染，图解内容从 `scripts/articles/` 读取；修改源文件后执行：

```bash
node 工程/scripts/build_articles.mjs
python3 工程/scripts/build_site.py
```

以上命令在仓库根目录运行。站点构建只生成一个根首页与 `工程/pages/category.html`。深色、混合配色在同页切换，保留 URL 参数和可用时的浏览器偏好。直接打开文件使用内嵌数据；HTTP 阅读可从 `工程/config/` 刷新数据。

第三方 Markdown 渲染器位于 `scripts/vendor/`，许可证随文件保留。资源路径、文章登记和模板变更应同时反映在生成页中。

## 3. 推荐阅读

遵循 SHOW-R01：推荐从全部文章中按质量、读者任务覆盖、理解门槛、证据强度与组合互补性选取。新增稿先进入候选，与现有文章一起比较；首页保持一篇主推与若干互补文章。

选中理由写入 `config/featured.json` 的 `reason`，读者能带走什么写入 `summary`；README 同步推荐组合。推荐文案保留原有证据强度，设计、实测与推演各有边界。退出推荐的文章仍由分类页承接。

## 4. 路径变更与验收

移动文件前核对调用方、构建输入、输出、资源和导航。移动后同步更新 JSON、模板、脚本、README 与源码中的相对链接，保留正式文章的发布路径。

验收覆盖：

- 文章构建、站点构建，以及配置登记的文件与目录约束。
- 全站本地链接、锚点、CSS / JavaScript / SVG 资源与许可证位置。
- 首页推荐、五类专题、文章阅读与返回入口，HTTP 和直接打开文件均可用。
- 同页主题切换、专题返回、11–15 的图示放大和深入版回链。
- 桌面与移动宽度中的可见内容和整页溢出。

检查记录放入 `工程/复核/`，保留对象、范围和未核事项；机械结果不替代事实和语义核查。`config/project.json` 中的文章路径以仓库根目录为基准，检查器须显式传入该配置路径。

## 5. 提交与发布

按本会话授权执行提交与推送。提交前核对暂存范围、构建结果和本地过程材料的忽略状态；推送后核对远端提交。外部规范仓库的改动与本仓库分别记录和发布。
